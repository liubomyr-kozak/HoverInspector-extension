# Документація робочого процесу редагування сценарію

## Декларативний огляд

### Процес редагування сценарію (короткий список)
1. **Ініціалізація режиму редагування** - Завантаження існуючого сценарію або початок створення нового сценарію
2. **Управління формою** - Оновлення метаданих сценарію (назва, опис, категорія, теги)
3. **Управління кроками** - Додавання, видалення, оновлення та перевпорядкування кроків автоматизації
4. **Валідація** - Перевірка обов'язкових полів і конфігурацій кроків
5. **Збереження** - Збереження змін у сховище з автоматичним збереженням стану
6. **Скасування/Завершення** - Вихід з режиму редагування або завершення змін

---

## Детальний робочий процес редагування сценарію

### 1. Ініціалізація режиму редагування
**Процес:**
- Користувач ініціює редагування зі списку сценаріїв або створює новий сценарій
- Redux дія `editScenario(id)` або створення нового сценарію
- Стан компонента переходить в режим редагування (`isEditingScenario: true`)
- Дані форми завантажуються з існуючого сценарію або ініціалізуються порожніми
- ID активного сценарію встановлюється в Redux стан

**Крайні випадки:**
- **Одночасне редагування**: Лише один сценарій може редагуватися одночасно
- **Відновлення стану**: Стан редагування зберігається в сховище для відновлення після оновлення сторінки
- **Неправильний ID сценарію**: Грациозна обробка неіснуючих ID сценаріїв
- **Проблеми з дозволами**: Збої доступу до сховища обробляються з повідомленнями про помилки

### 2. Управління даними форми
**Процес:**
- Поля форми відстежуються в локальному стані (`scenarioFormData`)
- Валідація форми в реальному часі з зворотним викликом `handleFormChange()`
- Поля включають: назва, опис, категорія, масив тегів
- Дані форми синхронізуються зі станом Redux

**Правила валідації:**
- **Назва**: Обов'язкове поле, не може бути порожнім або містити лише пробіли
- **Опис**: Опціональне, без обмежень довжини
- **Категорія**: Опціональне строкове поле
- **Теги**: Опціональний масив, undefined значення фільтруються

**Крайні випадки:**
- **Порожня назва**: Повідомлення про помилку "Будь ласка, введіть назву для сценарію"
- **Спеціальні символи**: Немає обмежень на символи в будь-якому полі
- **Довгі введення**: Немає явних обмежень довжини, але можуть застосовуватися обмеження сховища
- **Маніпуляції з масивами**: Масив тегів належним чином фільтрується для undefined значень

### 3. Система управління кроками
**Процес:**
- Кроки керуються через Redux дії з автоматичним збереженням
- Доступні операції: додавання, видалення, оновлення, перевпорядкування
- Кожна операція викликає `persistEditingStateWatcher` для синхронізації сховища
- Дані кроку включають: тип, xpath, alternativeXpaths, значення, прапори

**Операції з кроками:**
- **Додати крок**: `addStep()` - Додає новий порожній крок до поточних кроків
- **Видалити крок**: `removeStep(index)` - Видаляє крок за вказаним індексом
- **Оновити крок**: `updateStep(index, field, value)` - Оновлює конкретне поле кроку
- **Перевпорядкувати кроки**: `reorderSteps(fromIndex, toIndex)` - Змінює послідовність кроків

**Доступні типи кроків:**
- `value` - Змінити значення елемента
- `click` - Взаємодія з кліком
- `hover` - Взаємодія з наведенням
- `input` - Введення тексту
- `select` - Вибір із випадаючого списку
- `navigate` - Навігація по сторінці
- `code` - Користувацький JavaScript код
- `function` - Викликати користувацьку функцію
- `redirect` - Перенаправлення URL
- `update` - Обробка нової сторінки
- `wait` - Затримка таймера
- `waitElementVisible` - Очікування видимості елемента
- `confirmation` - Діалог підтвердження користувача
- `notification` - Показати сповіщення
- `getText` - Витягти текст з елемента

**Крайні випадки:**
- **Індекс поза межами**: Валідація операцій з кроками на правильних індексах
- **Недійсні типи кроків**: Валідація типу проти enum StepType
- **Валідація XPath**: Підтримка альтернативних XPath для надійності націлювання на елементи
- **Циклічні посилання**: Кроки функцій, що викликають самі себе або створюють цикли
- **Відсутні обов'язкові поля**: Кроки з неповними конфігураціями
- **Автооновлені XPaths**: Обробка автоматично оптимізованих селекторів

### 4. Розширена конфігурація кроків
**Процес:**
- Кожен тип кроку має специфічні вимоги до полів
- Кроки на основі XPath підтримують альтернативні селектори для надійності
- Кроки навігації включають опціональне керування виконанням
- Кроки Code/Function дозволяють виконання користувацького JavaScript

**Деталі полів кроків:**
- **type**: Обов'язкове значення enum StepType
- **xpath**: Селектор елемента (обов'язковий для кроків взаємодії з DOM)
- **alternativeXpaths**: Масив резервних селекторів для надійності
- **value**: Вхідне значення або параметр (для кроків value/input/code)
- **xpathAutoUpdated**: Прапор, що вказує на автоматичну оптимізацію селектора
- **enableNavigation**: Перемикач для виконання кроків навігації під час відтворення

**Крайні випадки:**
- **Недійсний XPath**: Обробка неправильного синтаксису селектора
- **Елемент не знайдено**: Грациозне повернення до альтернативних XPaths
- **Динамічний вміст**: Механізм автооновлення XPath для змін DOM
- **Елементи крос-фреймів**: Обмеження області XPath
- **Обмеження безпеки**: Вимоги пісочниці для виконання коду
- **Залежності функцій**: Валідація доступності користувацьких функцій

### 5. Інтеграція з записом
**Процес:**
- Режим запису може переходити в режим редагування
- Записані кроки автоматично заповнюють інтерфейс редагування
- `saveRecording()` переключається в режим редагування та ініціює збереження
- Стан запису зберігається під час переходів редагування

**Потік від запису до редагування:**
1. Користувач зупиняє запис через `saveRecording()`
2. Статус змінюється на `ScenarioStatus.EDITING`
3. Вкладка переключається на перегляд сценаріїв
4. Стан редагування зберігається в сховище
5. Кроки з запису стають редагованими

**Крайні випадки:**
- **Переривання запису**: Обробка часткових даних запису
- **Конфлікти запису**: Управління одночасними станами запис/редагування
- **Запис між вкладками**: Синхронізація стану запису
- **Збої сховища**: Запобігання втраті даних запису

### 6. Система збереження та персистентності
**Процес:**
- Операція збереження валідує дані форми та створює об'єкт Scenario
- Розрізнення між створенням нового сценарію та оновленням існуючого
- Автоматичне збереження стану редагування для відновлення після збоїв
- Синхронізація стану Redux зі сховищем

**Потік збереження:**
1. Валідація форми (назва обов'язкова)
2. Створення об'єкта сценарію з метаданими та кроками
3. Підготовка payload (з/без ID для нових/існуючих)
4. Відправлення Redux дії (`saveScenarioWatcher`)
5. Збереження в сховище через saga middleware
6. Стан редагування зберігається (не очищується після збереження)

**Деталі персистентності:**
- **Негайне збереження**: Кожна операція з кроками автозберігається в сховище
- **Відновлення стану**: Повний стан редагування відновлюється при оновленні сторінки
- **Вирішення конфліктів**: Останній-запис-перемагає для одночасних модифікацій
- **Обмеження сховища**: Управління квотою сховища браузера

**Крайні випадки:**
- **Перевищення квоти сховища**: Обробка помилок для обмежень сховища
- **Проблеми з мережею**: Можливість офлайн збереження та синхронізації при повторному підключенні
- **Одночасні модифікації**: Оптимістичні оновлення з виявленням конфліктів
- **Недійсні дані**: Валідація схеми перед збереженням
- **Пошкоджений стан**: Механізми відновлення для неправильних збережених даних

### 7. Обробка скасування та виходу
**Процес:**
- Операція скасування скидає форму та очищає стан редагування
- `handleCancel()` відправляє дії скидання
- Стан редагування сховища очищається через `clearEditingStateWatcher`
- Компонент повертається до списку

**Потік скасування:**
1. Скидання форми через `automationActions.resetScenarioForm()`
2. Стан редагування очищається зі сховища
3. Стан компонента повертається в режим списку
4. Незбережені зміни відкидаються

**Крайні випадки:**
- **Незбережені зміни**: Немає діалогу підтвердження (негайне скасування)
- **Збій очищення сховища**: Грациозна обробка помилок персистентності
- **Несумісність стану**: Надійне очищення стану та валідація
- **Часткові операції**: Очищення неповних модифікацій кроків

### 8. Управління станом UI
**Процес:**
- Умовний рендеринг на основі станів запису та редагування
- Кнопки заголовка та підвалу на основі порталу для контекстних дій
- Стани завантаження та обробка помилок у всьому інтерфейсі
- Зворотний зв'язок валідації форми та повідомлення користувача

**Умови стану:**
- **Активний запис**: Показує інтерфейс запису з опціями паузи/зупинки
- **Режим редагування**: Показує форму сценарію та редактор кроків
- **Режим списку**: Показує список сценаріїв з опціями створення/запису
- **Завантаження**: Відображає спінер завантаження під час асинхронних операцій

**Крайні випадки:**
- **Переходи станів**: Плавні переходи між режимами
- **Стани помилок**: Грациозне відображення помилок та опції відновлення
- **Тайм-аути завантаження**: Обробка довгих операцій
- **Відгук UI**: Продуктивність компонентів з великими списками кроків
- **Витоки пам'яті**: Належне очищення слухачів подій та підписок

## Примітки з архітектури системи

### Потік стану Redux
- **Дії**: CRUD операції сценаріїв, управління кроками, переходи станів
- **Редуктори**: Незмінні оновлення стану для сценаріїв та стану редагування
- **Саги**: Асинхронні операції для сховища, валідації та побічних ефектів
- **Селектори**: Ефективні запити стану з мемоїзацією

### Архітектура сховища
- **Основне сховище**: API сховища розширення браузера
- **Збереження стану**: Стан редагування автоматично зберігається
- **Система відновлення**: Повне відновлення стану при оновленні сторінки
- **Цілісність даних**: Валідація схеми та відновлення помилок

### Архітектура компонентів
- **Компоненти-контейнери**: Управління станом, підключені до Redux
- **Компоненти презентації**: Чисті UI компоненти з props
- **Компоненти порталу**: Контекстно-залежні кнопки дій
- **Компоненти форм**: Контрольовані введення з валідацією

Цей комплексний робочий процес забезпечує надійне редагування сценаріїв з розширеною обробкою помилок, збереженням стану та оптимізацією користувацького досвіду.
