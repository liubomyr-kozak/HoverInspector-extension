# Послідовність роботи системи автоматизації

Цей документ описує послідовність роботи системи автоматизації, зосереджуючись на змінах стану та різних типах дій.

## Загальний огляд

Система автоматизації побудована з використанням Redux для управління станом та Redux-Saga для обробки побічних ефектів. Вона дозволяє користувачам створювати, керувати та виконувати сценарії автоматизації, а також визначати користувацькі функції, розклади та тригери.

## Структура стану

Стан автоматизації організований у кілька розділів:

1. **Колекції даних**
   - `scenarios`: Карта ID сценаріїв до об'єктів сценаріїв
   - `functions`: Карта ID функцій до об'єктів функцій
   - `schedules`: Карта ID розкладів до об'єктів розкладів
   - `triggers`: Карта ID тригерів до об'єктів тригерів
   - `executionHistory`: Карта ID історії виконання до записів історії виконання

2. **Стани завантаження**
   - `loading`: Стан завантаження для сценаріїв
   - `functionLoading`: Стан завантаження для функцій
   - `scheduleLoading`: Стан завантаження для розкладів
   - `triggerLoading`: Стан завантаження для тригерів
   - `executionHistoryLoading`: Стан завантаження для історії виконання

3. **Стан інтерфейсу**
   - `activeTab`: Поточна активна вкладка
   - `expandedScenarios`: Список розгорнутих ID сценаріїв  // node: не зрозуміло чи мені потрібне
   - `keepScenarioExpanded`: Прапорець для збереження сценаріїв розгорнутими після виконання // node: не зрозуміло чи мені потрібне

4. **Стан сценарію**
   - `currentSteps`: Кроки поточного редагованого сценарію
   - `isEditingScenario`: Прапорець, що вказує, чи редагується сценарій
   - `activeScenarioId`: ID активного сценарію
   - `recording`: Прапорець, що вказує, чи активний запис
   - `recordingPaused`: Прапорець, що вказує, чи призупинений запис
   - `recordedSteps`: Кроки, записані під час запису

5. **Стан виконання**
   - `executing`: Прапорець, що вказує, чи виконується сценарій
   - `currentStepIndex`: Індекс поточного кроку, що виконується
   - `executionProgress`: Відсоток прогресу виконання
   - `executionError`: Повідомлення про помилку, якщо виконання не вдалося
   - `executionStatus`: Статус виконання (виконується, успішно, помилка тощо)
   - `executionSpeed`: Множник швидкості для виконання
   - `paused`: Прапорець, що вказує, чи призупинено виконання
   - `pendingSteps`: Кроки, що очікують на виконання
   - `stepStatuses`: Карта індексів кроків до статусів виконання

6. **Стани функцій, розкладів та тригерів**
   - Подібні шаблони для кожного типу сутності з поточним елементом, активним ID та прапорцем редагування

## Послідовні зміни стану

### Процес початкового завантаження

1. Коли додаток запускається, початковий стан встановлюється з порожніми колекціями та прапорцями завантаження, встановленими на true.
2. Додаток відправляє дії завантаження для кожного типу даних:
   ```javascript
   dispatch(loadScenariosWatcher.getPayload());
   dispatch(loadFunctionsWatcher.getPayload());
   dispatch(loadSchedulesWatcher.getPayload());
   dispatch(loadTriggersWatcher.getPayload());
   dispatch(loadExecutionHistoryWatcher.getPayload());
   ```
3. Кожна дія завантаження запускає сагу, яка:
   - Встановлює відповідний прапорець завантаження на true
   - Отримує дані з локального сховища
   - Оновлює стан отриманими даними
   - Встановлює прапорець завантаження на false

### Взаємодія користувача та зміни стану

#### Створення/редагування сценаріїв

1. Користувач натискає "Додати сценарій" або "Редагувати" на існуючому сценарії
   - Зміни стану: `isEditingScenario` встановлюється на true, `activeScenarioId` встановлюється, якщо редагується
   - Для редагування: `currentSteps` заповнюється кроками сценарію

2. Користувач редагує деталі сценарію та кроки
   - Зміни стану: `currentSteps` оновлюється, коли користувач додає/видаляє/змінює кроки

3. Користувач зберігає сценарій
   - Дія: запускається сага `saveScenarioWatcher`
   - Сага генерує новий ID, якщо створюється новий сценарій
   - Сага зберігає в локальне сховище та оновлює сховище Redux
   - Зміни стану: карта `scenarios` оновлюється, стан форми скидається

#### Запис сценаріїв

1. Користувач починає запис
   - Дія: запускається сага `startNewRecordingWatcher`
   - Сага створює новий сценарій з назвою з часовою міткою
   - Зміни стану: `recording` встановлюється на true, `recordedSteps` ініціалізується порожнім

2. Користувач виконує дії, які записуються
   - Зміни стану: `recordedSteps` оновлюється з кожною записаною дією

3. Користувач призупиняє/відновлює запис
   - Зміни стану: `recordingPaused` перемикається

4. Користувач зберігає запис
   - Зміни стану: `currentSteps` встановлюється на `recordedSteps`, `recording` встановлюється на false, `isEditingScenario` встановлюється на true

#### Виконання сценаріїв

1. Користувач натискає "Відтворити" на сценарії
   - Дія: запускається сага `playScenarioWatcher`
   - Зміни стану: `executing` встановлюється на true, `activeScenarioId` встановлюється, `pendingSteps` заповнюється

2. Починається виконання
   - Зміни стану: `executionStatus` встановлюється на RUNNING, `stepStatuses` ініціалізується

3. Кожен крок виконується
   - StepExecutor виконує крок і повідомляє результат
   - Зміни стану: `currentStepIndex` оновлюється, `executionProgress` оновлюється, `pendingSteps` оновлюється, `stepStatuses` оновлюється

4. Виконання завершується або не вдається
   - Зміни стану: `executionStatus` встановлюється на SUCCESS/ERROR/CANCELLED, `executionError` встановлюється, якщо помилка, `executing` встановлюється на false

#### Керування функціями, розкладами та тригерами

Подібні шаблони застосовуються до функцій, розкладів та тригерів, зі змінами стану, що слідують тому ж потоку створення/редагування/збереження/видалення.

## Типи дій

### 1. Дії завантаження

Ці дії завантажують дані зі сховища та оновлюють стан:

- `loadScenariosWatcher`
- `loadFunctionsWatcher`
- `loadSchedulesWatcher`
- `loadTriggersWatcher`
- `loadExecutionHistoryWatcher`

Приклад потоку:
```
dispatch(loadScenariosWatcher) 
→ setLoading(true) 
→ getAllScenariosFromLocalStorage 
→ setScenarios(data) 
→ setLoading(false)
```

### 2. Дії збереження

Ці дії зберігають дані в сховище та оновлюють стан:

- `saveScenarioWatcher`
- `saveFunctionWatcher`
- `saveScheduleWatcher`
- `saveTriggerWatcher`
- `saveExecutionHistoryWatcher`

Приклад потоку:
```
dispatch(saveScenarioWatcher) 
→ generateUniqueId (якщо новий) 
→ saveScenarioToLocalStorage 
→ addScenario/updateScenario 
→ resetScenarioForm
```

### 3. Дії видалення

Ці дії видаляють дані зі сховища та оновлюють стан:

- `deleteScenarioWatcher`
- `deleteFunctionWatcher`
- `deleteScheduleWatcher`
- `deleteTriggerWatcher`
- `deleteExecutionHistoryWatcher`

Приклад потоку:
```
dispatch(deleteScenarioWatcher) 
→ removeScenarioFromLocalStorage 
→ removeScenario
```

### 4. Дії виконання

Ці дії контролюють виконання сценаріїв:

- `playScenarioWatcher`: Починає або зупиняє виконання сценарію
- `startNewRecordingWatcher`: Починає запис нового сценарію
- `stopRecordingWatcher`: Зупиняє запис

Приклад потоку для виконання:
```
dispatch(playScenarioWatcher) 
→ setActiveScenarioId 
→ setExecuting(true) 
→ setPendingSteps 
→ setExecutionStatus(RUNNING) 
→ StepExecutor.executeSteps 
→ [для кожного кроку: setCurrentStepIndex, setExecutionProgress, setStepStatus] 
→ setExecutionStatus(final status) 
→ setExecuting(false)
```

### 5. Дії стану інтерфейсу

Ці дії оновлюють стан інтерфейсу без впливу на дані:

- `setActiveTab`
- `toggleScenarioExpanded`
- `setScenarioExpanded`
- `collapseAllScenarios`
- `expandOnlyScenario`

### 6. Дії стану форми

Ці дії керують станом форми для редагування сутностей:

- `setIsEditingScenario`
- `setIsEditingFunction`
- `setIsEditingSchedule`
- `setIsEditingTrigger`
- Дії скидання для кожного типу форми

### 7. Дії керування кроками

Ці дії керують кроками в сценаріях:

- `setCurrentSteps`
- `addStep`
- `removeStep`
- `updateStep`
- `reorderSteps`

## Деталі потоку виконання

Виконання сценарію слідує цим крокам:

1. **Ініціалізація**
   - Встановлення ID активного сценарію
   - Встановлення прапорця виконання на true
   - Встановлення очікуючих кроків
   - Ініціалізація журналу виконання
   - Встановлення статусу виконання на RUNNING
   - Очищення статусів кроків
   - Встановлення всіх очікуючих кроків на статус PENDING

2. **Цикл виконання кроків**
   - Для кожного кроку:
     - Виконання кроку за допомогою StepExecutor
     - Оновлення індексу поточного кроку
     - Оновлення прогресу виконання
     - Оновлення очікуючих кроків
     - Оновлення статусу кроку на SUCCESS
     - Перевірка, чи слід зупинити виконання
     - Додавання затримки між кроками на основі швидкості виконання

3. **Завершення**
   - Встановлення статусу виконання на основі результату (SUCCESS/ERROR/CANCELLED)
   - Встановлення помилки виконання, якщо застосовно
   - Встановлення прапорця виконання на false
   - Скидання індексу поточного кроку
   - Очищення очікуючих кроків
   - Згортання сценарію, якщо не зберігається розгорнутим

## Висновок

Система автоматизації використовує добре структурований підхід до управління станом з Redux та Redux-Saga. Зміни стану слідують передбачуваному шаблону для завантаження, збереження, видалення та виконання сутностей автоматизації. Процес виконання обробляється класом StepExecutor, який керує виконанням окремих кроків і повідомляє результати назад до сховища Redux.
